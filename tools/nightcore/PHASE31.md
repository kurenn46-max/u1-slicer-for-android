# NIGHT CORE Phase 3.1

## ナイトからCodexへの引き継ぎ

Actionsの nightcore-phase31-directives を開きます。directives.json が判定データ、directives.schema.json が形式、directives.ja.md が日本語の指令書、codex-prompts.md が引き継ぎ候補です。

ナイトはヘッド、ベース、CI、指令ID、担当者を確認し、承認した候補を隔離ブランチのCodexに渡します。依存待ちの項目は日本語指令書とJSONに残ります。実行中の担当者を確認できない場合は引き継ぎ時に確認します。同じPR、ヘッド、ベース、障害種別に同じ指令IDを使います。

GitHub ActionsにはCodexセッションの起動経路を設定していません。ワークスペースではCodex CLIとChatGPTログイン状態を確認しました。読み取り専用設定の一時セッションはCloud実行環境で書き込み制限により初期化に失敗しました。コマンド生成から先の自動実行は未実証です。

## 限定修復

監査JSON復元は既存の手順を使います。指令書・Codex候補・Summaryが欠落した場合は、出所とSHA256を確認したPhase 3チェックポイントと指令JSONを使い、以下で欠落ファイルを再生成できます。既存の指令と再計算結果が違えば保留します。

    python3 tools/nightcore/directives.py DIRECTIVE_DIR --checkpoint PHASE3_DIR/phase3.json --repair-missing

同じ修復の2回目は0件を返します。元のログ、ソース、CI状態を変更しません。
